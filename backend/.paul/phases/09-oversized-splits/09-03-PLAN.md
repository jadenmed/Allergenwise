<objective>
## Goal
Extract the pass-branch certificate-issuance block (lines 205-348: cert-code collision-retry loop, activity-event inserts, ExamPassed email) out of `app/api/exam/submit/route.ts`'s POST handler into a standalone, directly-testable `issueCertificateForPassedExam()` function in `lib/learner/`, zero behavior change.

## Purpose
Audit item B11 (Tier 3, pure clarity + testability). The 325-line POST handler mixes request auth/validation, exam scoring, and certificate issuance (a security/entropy-sensitive retry loop with its own monitoring semantics) in one function. Today it's only exercised indirectly via full-route tests; extracting makes the collision-retry and exhausted-budget paths unit-testable in isolation, matching the audit's explicit intent.

## Output
1 new lib file + 1 new focused unit test + trimmed route.ts. Identical DB writes, identical email send, identical response shape.
</objective>

<acceptance_criteria>

## AC-1: Extracted function preserves the cert-code retry loop exactly
Given a passed exam attempt with `restaurant_id` set
When `issueCertificateForPassedExam()` runs and hits 0, 1, 2, or 3 consecutive `23505` collisions on `certificates.insert`
Then it retries up to `MAX_CERT_INSERT_ATTEMPTS = 3` fresh `generateCertCode()` draws, writes `cert_code_collision_retry` activity events for each non-final collision, and writes `cert_issuance_retry_exhausted` only when all 3 attempts collide — identical to current behavior

## AC-2: Non-collision insert errors still bail without a certificate
Given a `certificates.insert` error with any code other than `23505`
When the function runs
Then it logs via `console.error('[exam/submit] cert insert error:', ...)`, leaves `certCode`/`certificateId` undefined, and does not retry — matching current early-`break` behavior

## AC-3: cert_issued and exam_passed activity events + ExamPassed email unchanged
Given a certificate was successfully inserted
When the function completes
Then it inserts `cert_issued` then `exam_passed` activity events with identical payload shapes, then (in the existing try/catch, non-fatal on failure) looks up the restaurant's manager profile and sends the ExamPassed email via `resend.emails.send` through the same dynamic `await import('@/lib/email/client')`, with byte-identical subject/HTML copy including the score and preview cert code

## AC-4: route.ts behavior is unchanged end-to-end
Given the full POST handler after extraction
When an exam is submitted (pass or fail, with or without `restaurant_id`, with time-limit expiry, with already-submitted, with invalid body)
Then every existing status code, response JSON shape, and side effect (exam_attempts update, exam_failed event, cooldown calculation) is identical to pre-extraction — all three existing test files pass with zero modification
